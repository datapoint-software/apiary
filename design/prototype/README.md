# Prototype

A clickable prototype of Apiary's admin interface: every page in the sidebar, the account pages, sign-in and first run. It shows how the components fit together and how the interface behaves, including validation, dialogs, alerts and the date and time picker. All data is invented and lives in memory; reloading resets it.

- **Prototype controls:** the dashed button at the bottom right switches scenarios. **Cluster:** healthy, one replica down, or no quorum, where changes pause. **Server:** fast, slow, or failing. **Data:** sample, or a new install. It also opens the sign-in, first-run and not-found screens. The controls aren't part of Apiary.
- **Try:** add a route with mistakes in it, a loopback target or weights that don't add up; schedule a maintenance window; take the size limit off registry.example.com and see the warning, then change the default at the bottom of All routes; upload a certificate (put "mismatch" in the key); renew the failing certificate for legacy.example.com; invite someone; filter the audit log by a custom range; leave a route with unsaved changes; open Traffic → Stacks, then `shop`, and use the dashed row to simulate an apply that works or fails; see the fields its labels lock on shop.example.com/api; add a stack, which creates its first pipeline token; review tokens under Access → Pipeline tokens; open Cluster → Trusted proxies, try a request from 192.0.2.1 and from 173.245.48.10, add 104.16.0.0/13 to see the public-range warning and 0.0.0.0/0 to see it refused; under Traffic → Redirects, redirect /sale on shop.example.com to /offers and watch the example under the switch, then try /api (it would hide a route) and /sale/2026 (a loop); open shop.example.com and see its path redirects between Targets and Certificate; under Traffic → Certificates, see the "Checked with" column and the failing Azure provider, open `*.example.com` and use "Switch them" to move more hostnames onto the wildcard, and Request certificate for `*.example.com` with HTTP-01 (refused) or `vpn.corp.example.com` (Office DNS is suggested, with the CNAME to create); under Traffic → DNS providers, add a provider, switch its type and choose a separate challenge zone to see the CNAME preview, test the Azure one (it fails) and try to delete Hetzner (in use); open the route for grafana.corp.example.com and change "Checked with" to the Azure provider (refused: it doesn't prove that hostname).
- **Patterns it settles:** validation (see Validation), confirmations that name what is affected and, when it can't be undone, ask you to type the name, writes locked while the cluster has no quorum, and every time in UTC.
